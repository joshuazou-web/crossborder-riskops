## 这一版是写给谁的

**招聘方的初筛人,不是工程师。**

他们要在两分钟内判断的是:这个人是不是真做过东西,值不值得转给业务面试官。所以片子里留的是**问题、规模、产品判断、一个记得住的亮点、以及怎么验证**——导入图、阈值标定方法、AST 断言这些都留在仓库里,给他们转交的那个人看。

不出现任何公司名称。它面向所有金融科技方向的岗位,不针对特定一家。

## 00:00–00:17 这是什么

> 跨境支付反洗钱预警调查与风险运营平台。
>
> 数据全部由固定随机种子生成,不涉及任何真实机构、客户或交易。
>
> 它要解决的问题很具体:预警远多于人手,今天该看哪一批?

*画面:反洗钱运营总览顶部,合成数据横幅与四个 KPI。*

## 00:17–00:36 漏斗就是产品

> 四万笔跨境转账,一千六百多次原始预警触发。
>
> 去重后九百五十七条,聚合成六百九十三个案件。
>
> 而一个这个规模的团队,今天只打得开两百四十二个。这个漏斗就是产品本身。

*画面:向下滚到「从预警到一个能干活的队列」漏斗图。*

## 00:36–00:54 队列,以及诚实的那一半

> 队列按调查优先级排序,在复核容量处切一刀。
>
> 注意这句话:容量线以下的案件不等于已排除风险,它只是没有被人看过。
>
> 评测报告里有专门一行,报告有多少风险模式正躺在这个积压里。

*画面:反洗钱预警队列,蓝色提示框与优先级分档。*

## 00:54–01:19 工作台 ← 全片最长的一段

> 打开优先级最高的案件。三条相互独立的风险模式同时指向这一个账户。
>
> 优先级由八个因子构成,每个因子的贡献都摊开写着 —— 不认同排序的人,能看到是哪一项把它顶上来的。
>
> 左边是证据。右边是:有什么会推翻它。
>
> 并排,不是上下。因为被队列压着的复核人自上而下读,而且会提前停。

*画面:调查工作台,从案件摘要滚到优先级明细,再滚到证据/反证双栏。*

## 01:19–01:39 它拒绝做什么

> 处置只有五种:结案、监测、补材料、强化复核、升级。
>
> 没有任何一项叫「认定洗钱」「已上报」或「冻结账户」—— 不是灰掉,是根本不存在。
>
> AI 不能记录任何处置结论。而且整个检测闭环里,一次模型调用都没有。

*画面:处置控件区,五个选项与必填理由框。*

## 01:39–02:02 数字,以及我自己会先查的那一行

> 原始预警精确率百分之二十二,复核容量内百分之八十七。
>
> 这个差,就是排序创造的价值。
>
> 而我自己最先去查的是这一行:故意造在阈值之外的场景,只召回了百分之十六。
>
> 如果这个数字高,说明检测器在打噪声,上面所有指标都不值钱。

*画面:反洗钱评测页,「排序值多少」与「第一个该去查的数字」。*

## 录音与合成

按段停顿,段与段之间留半秒,不必追求连贯——画面切分本来就在段边界上。

```bash
ffmpeg -i docs/demo/demo-zh.mp4 -i narration.m4a -c:v copy -c:a aac -shortest docs/demo/demo-zh-narrated.mp4
```

音轨比画面短会在结尾留静音,长了会被 `-shortest` 截断。差得多的话,先看是不是某一段念得太快,而不是去改视频。

## 重新生成画面

改了界面或想调节奏,重跑:

```bash
python -m streamlit run app/Home.py
python scripts/capture_demo_video.py
```

每段的时长写在 `scripts/capture_demo_video.py` 的 `BEATS` 里,和上面的段落一一对应。改了这里的字,就要改那里的秒数——脚本会检查每段画面是否够长,不够会直接报错而不是悄悄剪短。

**一个已经踩过的坑**:滚动前必须先把鼠标移到正文栏。Playwright 的光标默认在 (0, 0),那个位置落在侧边栏上,滚轮滚的是导航而不是页面——录出来的画面会一直停在页面顶部,而旁白已经在讲底部的内容了。
